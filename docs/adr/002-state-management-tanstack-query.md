# 002. Управление состоянием с TanStack Query

## Статус
Accepted

## Контекст
В проекте Interactive Dashboard Frontend требовалось решение для управления серверным состоянием, которое обеспечивало:

- Кэширование API-ответов для улучшения производительности
- Автоматическую синхронизацию данных с сервером
- Обработку состояний загрузки и ошибок
- Оптимистичные обновления
- Удобную работу с пагинацией и фильтрацией

Традиционные подходы (Redux, MobX) были бы избыточными для наших задач, а простое useState/useEffect не обеспечивало необходимого уровня функциональности.

## Решение
Было решено использовать TanStack Query (бывший React Query) для управления серверным состоянием в сочетании с React Context для клиентского состояния.

TanStack Query предоставляет:

- **Кэширование** - автоматическое кэширование ответов с настраиваемым временем жизни
- **Синхронизацию** - автоматическое обновление данных при изменении
- **Состояния** - встроенные состояния loading, error, success
- **Повторные запросы** - автоматические retry при ошибках
- **Оптимистичные обновления** - мгновенное обновление UI до ответа сервера

## Последствия

### Преимущества

1. **Производительность** - кэширование снижает количество API-запросов
2. **UX** - мгновенные обновления и индикаторы загрузки
3. **Простота** - меньше бойлерплейта по сравнению с Redux
4. **Надежность** - автоматическая обработка ошибок и retry
5. **TypeScript поддержка** - полная типизация данных и запросов
6. **DevTools** - отличные инструменты для отладки

### Недостатки

1. **Кривая обучения** - новая концепция для разработчиков
2. **Сложность отладки** - кэширование может усложнить отладку
3. **Размер бандла** - дополнительная зависимость

### Влияние на систему

- Все API-вызовы проходят через TanStack Query
- Состояние загрузки и ошибок обрабатывается централизованно
- Кэширование настроено на 5 минут для большинства запросов
- Мутации автоматически инвалидатируют相关 кэш

## Альтернативы

### Альтернатива 1: Redux Toolkit
- **Описание**: Полнофункциональный state management
- **Почему не выбрана**: Избыточная сложность для нашего случая, больше бойлерплейта

### Альтернатива 2: MobX
- **Описание**: Реактивный state management
- **Почему не выбрана**: Меньшая TypeScript поддержка, другие концепции

### Альтернатива 3: SWR
- **Описание**: Альтернативная библиотека для server state
- **Почему не выбрана**: Меньше функциональности, менее зрелая экосистема

### Альтернатива 4: useState + useEffect
- **Описание**: Базовые React хуки
- **Почему не выбрана**: Нет кэширования, много бойлерплейта для каждого запроса

## Реализация

### Базовый хук для запросов

```typescript
// src/features/dashboard/hooks/useStatsQuery.ts
import { useQuery } from "@tanstack/react-query";
import { fetchStats } from "../api/dashboardApi";

export function useStatsQuery(filters: DashboardFilters) {
  return useQuery({
    queryKey: ["stats", filters],
    queryFn: () => fetchStats(filters),
    staleTime: 5 * 60 * 1000, // 5 минут
    cacheTime: 10 * 60 * 1000, // 10 минут
    retry: 3,
    retryDelay: attemptIndex => Math.min(1000 * 2 ** attemptIndex, 30000),
  });
}
```

### Мутации с инвалидацией кэша

```typescript
// src/features/admin/hooks/useAdminPanel.ts
import { useMutation, useQueryClient } from "@tanstack/react-query";
import { registerUser } from "../api/usersApi";

export function useRegisterUser() {
  const queryClient = useQueryClient();
  
  return useMutation({
    mutationFn: registerUser,
    onSuccess: () => {
      // Инвалидируем кэш пользователей
      queryClient.invalidateQueries({ queryKey: ["users"] });
    },
    onError: (error) => {
      console.error("Registration failed:", error);
    },
  });
}
```

### Конфигурация QueryClient

```typescript
// src/app/main.tsx
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 5 * 60 * 1000, // 5 минут
      cacheTime: 10 * 60 * 1000, // 10 минут
      retry: 3,
      refetchOnWindowFocus: false,
    },
    mutations: {
      retry: 1,
    },
  },
});
```

## Стратегия кэширования

### Типы запросов

1. **Статические данные** (справочники) - 30 минут кэш
2. **Динамические данные** (статистика) - 5 минут кэш
3. **Пользовательские данные** - 10 минут кэш
4. **Административные данные** - без кэша

### Инвалидация кэша

- **Автоматическая** - при мутациях
- **Ручная** - при явном обновлении
- **По событию** - при фокусе окна (опционально)

## Лучшие практики

1. **Используйте descriptive query keys** - для легкой отладки
2. **Настраивайте staleTime** - в зависимости от типа данных
3. **Обрабатывайте ошибки** - на уровне хуков
4. **Используйте suspense** - для сложных сценариев загрузки
5. **Оптимизируйте ререндеры** - с помощью select в useQuery
